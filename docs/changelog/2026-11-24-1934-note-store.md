# Note storage over SAF, one directory per note

- `:core` has `app.screenscratch.core.store`: a `FileTree` abstraction shaped after SAF (one-call listings, nothing replaces an existing name) and `TreeNoteStore`, the only implementation of the note rules. `JavaFileTree` backs the JVM tests and suits app-private storage.
- Notes are `<id>/note.json` plus `<id>/assets/<sha-256>.<ext>`. Ids are creation time plus random bits and never change ([ADR](../adr/2026-11-24-1934-note-directory-named-by-id.md)). `note.json` is opaque to the store; callers pass the title and modified time.
- Saves go through `note.json.tmp`. Reads fall back to it when `note.json` is missing or the caller's parser throws ([ADR](../adr/2026-11-24-1934-note-json-wins-over-tmp.md)). A JVM test interrupts a save at every step and checks that the note still reads back as the old or the new version.
- Identical asset bytes are stored once. `deleteUnreferencedAssets` removes what the caller no longer references, including interrupted asset writes.
- The library index is one JSON file in app-private storage. A refresh lists the root once and re-reads only note directories whose modified time changed. Android 12 reports those times in whole seconds, so a time within 3 s of now isn't trusted and that note is read again on the next refresh.
- `:app` has `SafFileTree` (one `buildChildDocumentsUriUsingTree` query per directory, `"wt"` writes) and `NoteFolder` (the `OpenDocumentTree` picker, persisted grant, remembered root, lost-permission state).
- Instrumented tests run the store over SAF against a test-only `DocumentsProvider` in the test APK.
- Measured on the API 31 tablet emulator with 200 notes: one root listing takes 6–8 ms. A library refresh with nothing changed takes about 6 ms. A new store loading the index file takes 20 ms. A full rebuild takes 300–390 ms. The `DocumentFile` pattern of one query per getter takes 380–590 ms.
