# Inking canvas

- `app.screenscratch.canvas` draws a note and takes pen input. `NoteCanvas(controller)` hosts it in Compose, and `CanvasController` is its surface: tool, colour, width, "Pen only", button swap, dark mode, undo and redo, the observable note, and viewport commands.
- Pan with one finger when "Pen only" is on, or with the pen in pan mode. Pinch with two fingers to zoom between 20% and 800%. "Fit" shows the first page or all content. The infinite canvas and A4, Letter and screen pages are drawn, with the gap between pages, paper colour, a light shadow and a desk colour around them.
- Strokes are filled from cached perfect-freehand outlines: width as size, thinning 0.65, smoothing 0.5, streamline 0.3, round caps, simulated pressure when none was reported. Shapes, lines with arrowheads, images (through an `AssetImages` loader) and text boxes (through a `TextBoxRenderer`, plain text for now) are drawn too. Only elements whose bounds meet the view are drawn.
- Dark mode reverses greys (near-black ink becomes near-white) and lifts chromatic ink to a readable lightness with its hue kept. This happens at draw time only, in OKLab; images are left alone.
- In-progress ink goes into `LowLatencyCanvasView`'s front buffer as pressure-width capsules that match the final outline's width ([2026-11-24-2005-in-progress-ink-as-pressure-capsules](../adr/2026-11-24-2005-in-progress-ink-as-pressure-capsules.md)). At pen-up the stroke becomes a `Stroke` snapped to the `note.json` grid. The low-latency view is added after the window's first frame, and the hand-cut hole is kept. Without it, the canvas view inks by itself.
- After a pan, zoom or edit, the front buffer is cleared while hidden. The first draw of the next stroke re-renders the visible note into it. The canvas test screen can switch the buffer to hold only ink over the canvas view instead, which needs no re-render.
- Input: a pen side button erases while held and the other cycles pen → pan → select, hovering or touching, with a swap setting. Fingers are ignored while the pen is down, `ACTION_CANCEL` drops the stroke, and pen-down requests unbuffered dispatch. `input-motionprediction` is not used: predicted ink can't be removed from the persistent front buffer.
- The eraser removes whole strokes whose outline it touches. Each erase gesture is one undo step. Undo keeps up to 200 note snapshots, which share their elements, and at most a million element references.
- "Canvas test" on the main screen has a full-screen canvas, a plain toolbar, and the latest pen-down latency and frame times. Its note is saved in app-private storage.
- On the API 35 tablet emulator, with events from `adb shell input`, the canvas takes 0.3–5 ms from receiving pen-down to finishing its first front-buffer draw. Input dispatch before that was 2–21 ms. Re-recording the note into the buffer after a pan took 0.1–0.6 ms of CPU. The emulator's software GPU then took about 67 ms (median) to hand that frame to the display, against about 38 ms with only ink in the buffer. The front buffer's real fast path runs only on a device.
- Tests: unit tests for viewport math, the colour transform, input routing, the eraser, history and stroke building. Robolectric renders a sample note in light and dark to `app/build/outputs/canvas-render/`. On-device tests inject stylus strokes after a pan and pinch, cycle tools with the side button, erase with the other, cancel a stroke, and log latency.
